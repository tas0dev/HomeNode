# HomeNode UI設計書

バージョン：0.1.0  
対象：スマートフォン・PCのWebブラウザ  
適用範囲：HomeNode Web

## 1. 設計目的

HomeNodeは、Raspberry Pi 4を介して1台のWindowsデスクトップPCを管理するWebアプリケーションである。UIの役割は、対象PCの状態を即座に把握し、必要な電源操作を安全かつ少ない操作で実行できるようにすることである。

基本方針は「Minimal + Control」とする。一般的な分析ダッシュボードのような高密度な装飾や多数のカードではなく、情報を整理する余白、細い区切り線、明確な文字階層を採用する。スマートフォンの縦画面を基準とし、デスクトップ画面にも対応する。

## 2. 確定したデザイン原則

1. ホーム画面にはPCの電源状態、電源操作、CPU・GPU使用率、メモリ使用量、Sunshineの状態を表示する。
2. 電源操作は画面下部、ナビゲーションの直上に配置する。
3. 下部ナビゲーションは `Overview`、`Metrics`、`Logs` の3項目とする。
4. 色は白・黒・中立グレーのみとし、正常・異常を色の違いだけで表現しない。
5. 面を区切るカードの多用を避け、背景を一体化して細い区切り線を使う。
6. 使用率は数値とリアルタイム折れ線グラフで示す。ホーム画面の時間範囲は直近60秒とする。
7. シャットダウンと再起動などの電源操作は確認ダイアログを経由する。
8. ヘッダーにはPC名と稼働状態を文字で表示する。状態アイコンは使わない。
9. `Metrics` は一覧から独立した詳細ページへ遷移する。
10. 詳細グラフは複数系列を重ね、時刻のタップによる値の確認と系列の表示切り替えに対応する。
11. `Logs` は簡潔な一覧形式とし、重要度とコンポーネントで絞り込む。
12. 電源操作は単一の `Power` ボタンからメニューを開く。
13. 画面遷移、メニュー開閉、数値更新、グラフ更新にアニメーションを使用しない。

## 3. 視覚仕様

### 3.1 色

初期バージョンはダーク背景の完全モノクロとする。すべての指定値は無彩色であり、青・緑・赤などのアクセント色は使用しない。

| 用途 | 値 |
|---|---|
| ページ背景 | `#101010` |
| 主要文字 | `#F5F5F5` |
| 補助文字 | `#B8B8B8` |
| 弱い文字 | `#858585` |
| 区切り線 | `#383838` |
| メニュー・ダイアログ背景 | `#1A1A1A` |
| 主要操作面 | `#EDEDED` |
| 主要操作面上の文字 | `#101010` |
| 無効状態の文字 | `#777777` |

成功・失敗・警告はそれぞれ `ONLINE`、`ERROR`、`WARNING` などの明示的な文言で区別する。グラフ系列は線の濃淡、実線・破線・点線の組み合わせで識別する。

### 3.2 文字

通常のUIにはOS標準のサンセリフ体（`system-ui`）を使用する。数値は桁が動かないよう `font-variant-numeric: tabular-nums` を指定する。ログの識別子・時刻・技術情報には等幅フォント（`ui-monospace`）を使用する。外部フォントの読み込みを必須としない。

文字サイズの基準は本文15px、補助情報12〜13px、セクション名16〜18px、主要メトリクス28〜36pxとする。英字ラベルは短く保ち、説明文と確認ダイアログには日本語を使用する。

### 3.3 余白・境界

- モバイル画面の左右余白：16px
- セクション間隔：24px
- 情報行の最小高さ：48px
- 区切り線：1px
- タップ領域：最小44×44px
- 角丸：メニューやダイアログなどの一時的な面に限定し、基本表示は平坦にする
- 数値、ラベル、単位の位置は同一カテゴリ内でそろえる

## 4. 情報設計と画面遷移

| 画面 | パス | 目的 |
|---|---|---|
| Overview | `/` | PC状態の把握と電源操作 |
| Metrics | `/metrics` | 監視対象の一覧 |
| CPU詳細 | `/metrics/cpu` | CPUの系列グラフと数値 |
| GPU詳細 | `/metrics/gpu` | GPUの系列グラフと数値 |
| Memory詳細 | `/metrics/memory` | メモリ使用状況 |
| Network詳細 | `/metrics/network` | 通信速度・通信量 |
| Node詳細 | `/metrics/node` | Raspberry Piの状態 |
| Logs | `/logs` | イベントとエラーの確認 |

下部タブバーは全画面で固定する。詳細ページでも `Metrics` タブを選択状態に維持し、ページ上部に戻る操作を表示する。ブラウザの戻る操作にも対応する。

タブの下にコンテンツが隠れないよう、スクロール領域にはセーフエリアを含む下余白を確保する。電源ボタンは `Overview` にだけ表示し、タブバーの直上に固定する。

## 5. Overview画面

### 5.1 ヘッダー

左側に管理対象PCの表示名、右側に `ONLINE`、`OFFLINE`、`STARTING`、`SHUTTING_DOWN`、`RESTARTING`、`UNREACHABLE` のいずれかを文字で表示する。状態を色や丸印に置き換えない。

### 5.2 情報の並び

1. CPU：現在の使用率を大きく表示し、直近60秒の折れ線グラフを配置する。
2. GPU：現在の使用率を大きく表示し、直近60秒の折れ線グラフを配置する。
3. Memory：使用量、総容量、使用率を1行にまとめる。
4. Sunshine：`READY`、`RUNNING`、`STOPPED`、`UNKNOWN` などの状態と接続先情報への導線を表示する。

情報領域はカードで囲まず、1pxの区切り線と余白で分離する。CPU/GPUグラフは秒単位で更新し、補間による滑らかな移動を行わない。

### 5.3 電源操作

画面下部に単一の `Power` ボタンを固定する。タップするとその時点で利用できる操作だけをメニューに表示する。

| PC状態 | 表示する操作 |
|---|---|
| OFFLINE | Power On |
| ONLINE | Shutdown、Restart |
| STARTING / SHUTTING_DOWN / RESTARTING | 実行中の状態を表示し、新たな操作は無効 |
| UNREACHABLE | 電源操作を無効にし、接続状態の確認を促す |

いずれの電源操作も実行前に確認ダイアログを表示する。確認ダイアログには対象PC名、操作名、想定される影響、`キャンセル` と `実行` を表示する。特にシャットダウンと再起動では未保存の作業が失われる可能性を明示する。

操作要求を送信した時点で「成功」と表示しない。Serverの受付、Agentの受付、実際の状態遷移を区別して表示する。

### 5.4 停止時・切断時

Windows PCがOFFLINEの場合、CPU/GPU/Memoryの数値は `—` と表示する。古い数値を現在値として表示しない。最新データの通信が途絶えた場合は、数値の代わりに `更新停止` と最終更新時刻を示す。

## 6. Metrics画面

### 6.1 一覧

`CPU`、`GPU`、`Memory`、`Network`、`Raspberry Pi` を縦方向の一覧として表示する。各行には項目名と代表値、詳細ページへ移動できることを示す控えめな右向き記号を置く。行全体をタップ可能とする。

### 6.2 詳細ページ

詳細ページ上部にはカテゴリ名、戻る操作、最新値を配置する。その下に1つのメイングラフを置き、選択した複数系列を重ねて描画する。グラフ下には系列のオン・オフ操作と各指標の最新値を配置する。

グラフの初期時間範囲は直近60秒とする。サーバーのメモリ上に保持された短期データを表示し、長期履歴機能は設けない。

使用率・温度・クロックなど、単位が異なる系列を重ねる場合は、最大2種類の単位を左右の独立した数値軸に割り当てる。3種類目の単位を追加しようとした場合は、いずれかの既存単位を非表示にするよう促す。数値を暗黙に正規化して同じ軸に置かない。

グラフ上をタップすると最も近い取得時刻を選択し、縦のガイド線と各系列の実測値を表示する。グラフの系列は線種・濃淡・凡例で区別し、色に依存させない。

グラフの更新はサンプル受信ごとの即時再描画とし、アニメーションを挟まない。取得不能なセンサーは凡例に `取得不可` と表示する。

### 6.3 項目別情報

| 詳細ページ | 主要指標 |
|---|---|
| CPU | 使用率、温度、クロック、モデル名 |
| GPU | 使用率、温度、クロック、VRAM、消費電力、モデル名 |
| Memory | 使用量、空き容量、総容量、使用率 |
| Network | 送受信速度、累計通信量、接続速度、IPアドレス |
| Raspberry Pi | CPU使用率・温度、メモリ、稼働時間、Wi-Fi状態 |

## 7. Logs画面

ログは新しい順に並ぶシンプルな一覧形式とする。1行には時刻、発生元、重要度、短いイベント名を表示する。項目をタップすると詳細ページまたは詳細領域にタイムスタンプ、イベントID、メッセージ、付随情報を表示する。

上部に以下の絞り込みを配置する。

- 重要度：`ALL`、`DEBUG`、`INFO`、`WARN`、`ERROR`
- 発生元：`ALL`、`SERVER`、`AGENT`、`SUNSHINE`、`NODE`

絞り込みは即時適用し、一覧の状態をページ内で保持する。全文検索や日付範囲検索はv0.1.0では設けない。最新ログ受信時に閲覧中の内容が勝手にスクロールしないようにする。

## 8. 共通インタラクション

- タブ切り替え、ページ遷移、数値更新、メニュー開閉にアニメーションを使わない。
- 主要操作のタップ後は `要求中`、`受付済み`、`失敗` を文字で区別する。
- 同一の電源要求が処理中である間は二重送信を禁止する。
- 通信が失われた場合は、Web UIとPiの接続障害を明示する。
- Agentとの接続障害と、ブラウザからPiへの接続障害は別に扱う。
- ネットワーク復帰後は画面の再読み込みなしでデータ受信を再開する。
- 取得できない指標を `0` として表示しない。

## 9. レスポンシブ・アクセシビリティ

スマートフォンの幅320px程度から横スクロールなしで利用可能とする。大きい画面ではコンテンツ幅を最大960pxに制限し、広い余白を確保する。Metricsの一覧行や詳細指標は十分な横幅がある場合に限り2列に配置してよい。

キーボード操作、フォーカス表示、スクリーンリーダー用ラベルに対応する。グラフの情報は画像表現だけに依存させず、最新値と選択時刻の数値をテキストでも提供する。状態表現は必ず文字を伴う。

## 10. UI完了条件

1. スマートフォンで `Overview`、`Metrics`、`Logs` を利用できる。
2. CPU・GPUの60秒グラフが1秒間隔で更新される。
3. Metricsの5カテゴリから詳細ページへ移動し、戻る操作ができる。
4. 詳細グラフで時刻の値を確認し、系列を切り替えられる。
5. 単一のPowerボタンから適切な操作を選択し、確認を経て要求できる。
6. Logsを重要度と発生元で絞り込める。
7. Offline・通信断・データ欠損を誤解なく区別できる。
8. 全画面でモノクロを維持し、UIアニメーションを使用しない。
